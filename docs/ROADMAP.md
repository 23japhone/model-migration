# 后续工作与验收出口

本路线图记录当前已知缺口及建议顺序，不承诺日期、不授权自动实施。需求范围仍以 [功能规划汇总](MODEL_MIGRATION_FEATURE_PLAN_SUMMARY.md) 为准；路径契约唯一维护于 [架构第 9 节](ARCHITECTURE.md#9-路径与资源契约)，当前检查事实见 [验证](TESTING.md#当前验证基准)。

客户默认值与 prompt 补值、三文件交付、EvalScope 共用安装/续接/交接核验、路径兼容、功能输入预算及空闲优先共享 NPU 部署均已合入本地 `dev`，版本见 [项目当前状态](PROJECT_BRIEF.md#当前状态)。严格客户字段、环境选择与冻结、请求生成、子集选择、共享预算、恢复与整体发布已有离线回归；下表仅列仍待验收或建设的范围。

| 顺序/工作 | 前置与范围 | 验收出口 |
| --- | --- | --- |
| 1. 专项离线验收 | 在现有客户及旧接口回归基础上，补齐完整编排协议、取消与超时的专项验收 | 对应场景实际执行并保留终态、部分成果与资源归属证据；已有定向测试不能代替完整专项 |
| 2. 宿主发现与调用 | 选定宿主和安装方式；保留完整技能资源 | 宿主可发现、选择并调用所需入口，无重复/遗漏；不推断所有宿主递归兼容 |
| 3. 客户流程实机验收 | 当次明确主机、prompt、task.json、模型/数据、镜像及设备授权；核对真实 SDK、固定版本与硬件配方；历史已有部署功能及一项精度子集；本次续跑的直接部署功能和性能基线有独立证据，候选已退出，客户仍blocked | 取得全部必需精度项和三文件独立 ready 回执；续接前核对服务及实际资源版本，处理本次不再探针要求与交接契约的差异，保留已完成与失败证据。安装/配置漂移、上下文不足和失败续接仍需各自专项证据，不因部分成功自动重跑 |
| 4. 共享 NPU 实机验收 | 当次获准的可见设备池、合法 TP、真实模型/KV/运行开销配方；包含全部四卡被占用但逐卡预算满足的场景 | 真实驱动/容器共享启动、功能、精度和交付通过；验证固定比例、5%预留、启动前资源变化阻塞、自有 worker 完整归属及外部进程正常变化，保留失败和用户决策证据 |
| 5. 共用环境实机验收 | 迁移精度已有有效结果、获准性能入口及串行使用条件；此前下游本地子进程入口有命名空间限制；本次公开环境核验ready且宿主EvalScope性能侧已运行，精度侧尚未执行 | 先明确并验证实际执行命名空间，再核验 ready 和实际性能进程的 Python/env；两端 Python、CLI、版本有据才验收共用。perf 帮助或三文件导出不能替代；本仓不自动扩展性能执行或安装修复 |
| 6. 持续验证工具 | 明确维护范围和依赖策略后另立任务 | 补测试、复杂度/依赖边界工具或 CI，运行后才登记为可用门禁 |

离线验证不能替代实机验证；宿主验收和目标环境验收可在各自前置满足后独立安排。某项受阻不抹去其他项的有效证据，但不得宣称整仓交付通过。

镜像 editable 探测、原生数据集接口、token 长度、已退出同名容器自动替换及功能模板/预算修复均已有代码和相应验证。自动替换与新建服务功能也已在原服务器执行，具体范围见[验证记录](TESTING.md#当前验证基准)。这些修复不再列为待开发项；完整精度、导出和下游性能交接仍按上表独立验收。设备先搜索全空闲组合，必要时按占用卡数、TP和卡号选择满足逐卡预算的共享组合；该策略不代表已完成 TP 性能对比，详见[共享部署契约](../skills/vllm-model-migration/references/customer-observations.md#空闲优先与共享部署)。此前直接部署与单组性能基线的证据、失败候选和续接约束见[续跑记录](TESTING.md#2026-11-03-qwen35-27b-断点续跑与直接部署)，它们不把性能优化变为本Skill的自动执行职责。

当前交付包括客户模板与流程、旧接口兼容、三文件生成/导出及离线测试，以及规则文档、结构基线和随仓库提供的 [开发技能和审计工具](DEVELOPMENT_SKILLS.md)。未来任务遵循 dev 分支开发、commit 与本地合入分别授权、main 由用户手动同步的规则。AISBench 三文件交付不在当前验收承诺内，扩展需要另行明确需求。

EvalScope 任务质量对齐、未达标样本的 Token 定向复测和首异常位置的张量与算子对齐已合入本地 `dev`。单题 NPU 复测结合合成 GPU 数据验证了首个异常 Token 的定位，张量阶段使用双端合成证据验证了逐调用比较。同条件的真实 GPU/NPU 联合采集、从客户总入口到三文件交付的完整链路仍分别待实机验收。[任务质量验收](TESTING.md#2026-11-25-任务质量对齐单题验收) · [Token 预测验收](TESTING.md#2026-11-25-token-首个异常定位) · [张量比较验收](TESTING.md#2026-11-25-运行时张量与算子对齐)

SGLang 迁移、性能优化执行、量化/训练、多机调度、宿主插件发布等排除项不会因列出路线图成为隐含待办；扩大范围需要新的明确需求。
