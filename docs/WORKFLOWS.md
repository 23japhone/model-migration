# 工作流程

本文约束开发和业务执行过程。Git 权限以 [根规则](../AGENTS.md#git-硬约束) 为准；业务范围见 [功能规划](MODEL_MIGRATION_FEATURE_PLAN_SUMMARY.md)，调用与接口分别见 [架构](ARCHITECTURE.md) 和 [接口索引](INTERFACES.md)。步骤先后不自动形成业务依赖。

## 开发与两次授权

| 步骤 | 输入/前置 | 产出与完成标准 | 失败或恢复 |
| --- | --- | --- | --- |
| 只读核对 | 用户任务、规则、源码和 Git 状态 | 明确范围、基点、依赖、验证方式；记录 main 与远端状态 | 保留用户改动；远端不可达标记未核实，不自动同步 main |
| 建立工作分支 | 当前本地 dev、明确任务 | 从 dev 创建 codex 分支并记录起点；main 不变 | 同名分支先核对归属，不覆盖；必要时用隔离工作区 |
| 实现 | 已授权范围和验收条件 | 最小改动、适用的 Change Shape Map、失败边界及证据 | 局部失败不停止无依赖工作；扩大范围先说明并取得授权 |
| 验证与审查 | 当前完整差异 | 相关检查结果、已知失败分类、无未解决的本次可行动缺陷 | 修复本次缺陷后复验；不趁机修复无关业务问题 |
| commit 授权 | 可审查差异、文件范围、验证与残余风险 | 用户明确同意后，仅暂存本次文件并创建本地提交；提交标题和说明正文按根规则使用中文 | 未授权保持未提交；不得把实现请求解释为 commit 同意 |
| dev 合入授权 | 已有提交 ID、待合入差异、当前 dev | 用户另行同意后，本地 --no-ff 合入 dev；授权包括合并提交，合并标题和说明正文也须使用中文 | dev 已变化则检查集成差异并补相关验证；冲突解决不得扩展业务 |
| 交付 | 合入结果或当前授权停点 | 报告实际 Git 状态、main 未变及证据位置 | 未授权的步骤保持待办；不 push、不创建 PR，不自动删除分支 |

合入前后均核对 `main`；如果发现它与 `origin/main` 不一致，报告原始提交 ID 和查询时间，交由用户手动同步，禁止自动 reset 或快进。远端跟踪引用只是本地缓存，不能单独证明远端当前值。网络失败不等于提交一致。

纯文档工作使用链接、内容、策略和差异验证；业务变更需要对应行为验证。缺少测试框架不授权安装依赖或把零测试记成通过。默认用 `verification-runner`、`bug-focused-reviewer`、`ship-small` 完成验证、审查与交接，Git 授权边界始终保持。

上述工作流使用仓库内 `.agents/skills/` 的技能，完整入口和间接依赖见 [开发技能索引](DEVELOPMENT_SKILLS.md)。团队成员克隆后可读取这些文件并运行仓库内审计脚本；技能目录齐备不代表任意宿主的发现或任务行为已经验收，发现异常时核对具体宿主与所用路径。

规则、计划或任务新增工作流技能，或者已有技能新增其他技能引用时，在同一变更中执行 [新增技能纳入流程](DEVELOPMENT_SKILLS.md#新增工作流技能的纳入流程)，完成仓库副本、依赖闭包、来源记录及验证后再进入交付；缺少所需技能时只阻塞真实依赖步骤。

## 知识收尾

使用仓库内 `neat-freak` 核对本项目的源码、文档、规则、获准记忆及工作区状态。先只读盘点，再对差异记录权威来源、受影响位置、修订和验证；每个适用事实面使用技能规定的状态汇报。无部署目标时运行态为 `not-applicable`，未运行的业务验收仍为 `pending`，不能用本地合入或文档检查代替。

安全、可逆的文档修订仍在开发分支进行；技能资源按纳入流程维护。记忆默认只读，不直接修改 Codex 生成记忆；写入须有明确授权并使用环境规定的入口。已有业务缺陷继续登记在现有架构和路线图，不为收尾扩大业务范围或创建平行记录。

清场先列候选、说明归属及唯一未集成内容，再完整汇报并保留现场。使用该技能执行删除前，须在汇报后取得用户明确确认；未确认时只预览，不删除分支、worktree、临时库或中间产物。提交、合入和远端操作沿用根规则的授权边界；上一个任务的 Git 授权不自动延续到本次新增修订。

## 业务流程与完成边界

| 流程/目标 | 输入与真实依赖 | 产出、完成标准及验证 | 常见失败与继续方式 |
| --- | --- | --- | --- |
| 资产准备 | 本次 required 任务、模型/镜像/数据来源和适用版本资料 | 任务清单、身份、准备台账与交接；按契约核对实际内容 | 单项失败保留其他资产；阻塞其消费者，不用文件存在替代核验 |
| 模型迁移 | full 模型和镜像准备；目标版本、载体及功能要求 | precheck 路线、必要适配/注册、最终载体复验与真实功能证据 | 缺适配回执时交由 Agent 完成公开流程；缺前置只阻塞依赖项 |
| 语义复核续接 | 原始 verify 报告、完整响应和明确复核依据 | verify review → execute finalize，产生独立结果；总入口显式引用继续 | 保持原待复核/失败报告；不自动判通过、不重新部署 |
| 精度测量 | 有效部署、数据选择、原生配置和独立评测环境 | 逐项原生结果、有效性、可比性及目标结论；核验服务身份与样本覆盖 | 单项失败继续其他就绪项；缺 GPU 保留 NPU 测量，缺目标不宣称达标 |
| 历史分析 | 固定历史报告或原生产物及其来源 | 核对已有证据、指标和比较条件；不产生新推理或评分 | 缺历史来源保持 blocked/review_required，不用当前默认值补齐 |
| 完整流程交接 | 已完成部署及全部必需精度项；客户模式自动生成三文件候选和负载，旧导出接口接受显式候选 | 联合校验及独立导出 status=ready，三份配置路径及摘要齐备；EvalScope 客户 completed 包含交付，AISBench 当前仅支持精度执行 | 缺字段只阻塞导出，不抹除或重跑前序结果 |
| 服务收尾 | 原所有者、消费者完成状态及精确资源身份 | verify-agent 公开入口的 retained/stopped/unknown 证据 | borrowed 和复用迁移结果的服务保留；停止未确认不能声称释放 |

总入口的 preparation 与 dataset_preparation 分别服务部署和精度：数据失败不阻止部署，部署失败不阻止独立数据准备。当前实现顺序执行就绪项，规则不承诺并发 DAG、自动断点恢复或 exactly-once。

## Failure Containment Contract：失败隔离

修改流程前使用 `contain-workflow-failures`，记录每步的所有者、输出、前置、消费者、失败类型、诊断及最终状态影响。守卫和异常处理放在缺失条件的所属边界，不在顶层提前退出所有无关分支。

| 失败类型 | 判断与影响 | 应保留的证据 |
| --- | --- | --- |
| 分支局部 | 某资产、某评测或可选来源失败；阻塞真实消费者，继续独立项 | owner、阶段、原因、原始错误及有效部分结果 |
| 可重试 | 有证据表明条件变化后可能成功 | 当前失败与恢复依据；本仓不自动加重试，授权后新尝试不覆盖旧结果 |
| 必需依赖缺失 | 对应消费者无法安全执行 | blocked 原因和缺少的输入；不得用 skipped 隐藏必需失败 |
| 任务致命 | 取消、共享证据不可写、共享身份/状态损坏使全部剩余效果不安全 | 停止后续效果，尽可能保存终态、部分产物和资源未知状态 |
| 正常跳过 | 所选 scope 或预检路线确实不需要该步骤 | skipped 的业务理由，不声称该项已验证 |

总状态失败与继续执行是两个决策；不能因继续其他工作就制造整体成功。捕获能分类的异常，保留原因；不可恢复的共享证据错误不得吞掉。取消后的清理只能在原授权和精确身份范围内由资源所有者执行。

改变失败逻辑时验证成功、局部失败、依赖阻塞、独立继续、诊断保留、最终汇总、多项同时失败、取消及致命失败；不通过新增模式开关、统一大 catch 或无条件 return 隐藏新的职责。

## Task Continuity Contract：任务连续性

多步骤工作使用 `preserve-task-continuity`，在当前任务记录台账，不强制向仓库添加运行日志。台账字段为：步骤、具体成果、真实前置和依赖者、状态、证据、重试/恢复规则。状态使用 pending、running、succeeded、failed、blocked、skipped、cancelled。

失败后先保留错误与部分结果，标记真正缺少前置的步骤，立即继续其他已授权就绪项。不要用 `test && lint && docs` 的短路结果代替依赖判断，也不要仅因另一项失败而重跑已经成功的检查。

只有取消、授权失效、不安全继续、共享状态损坏或影响整体的必需用户选择等条件才停止全部工作。等待 commit/合并授权时，以该授权明确标记后续步骤 blocked，不把等待当作执行失败。交付时每个步骤有结果或明确的阻塞原因，保留所有有效证据。
