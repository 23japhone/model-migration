# 失败定位和保留

先检查回执的 operation、status 和 details.errors，再区分输入身份、源码差异、权重映射、定向记录和后续运行失败。每次 attempt 独立保留；修复实际原因后新运行，不覆盖失败记录。

- capture 阻塞：核对原始 config、预检 config/版本、来源完整树及资料摘要。变更请求需重新 capture，不能重写旧回执。
- 差异越界：审查新增/删除/mode 和允许范围；范围变更先确认仍属授权目标，不用扩大 allow 掩盖无关改动。
- 权重问题：查看 shard/index/key、dtype/shape、融合区间和排除理由；缺失/未知不自动忽略。
- 过期测试：源码 fingerprint 或 config 变化后重跑受影响真实定向检查，更新完整记录，不能只改摘要。
- 最终运行失败：读取注册/验证独立回执、完整日志及请求结果，按失败实际依赖保留其他成果。只在已授权范围内定向修复，再交由验证入口处理服务。

任何自动降级为关闭图像、dummy 权重、修改架构名或放宽语义判定的做法，都不能关闭原验收缺口。不得清理无关进程或使用全局 pkill。
