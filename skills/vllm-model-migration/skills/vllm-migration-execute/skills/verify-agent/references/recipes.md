# 显式运行配方与证据

先固定目标版本、资产内容和硬件，再选择模型支持的 dtype、TP、context、eager/graph、模态和模板。配方是输入；不得根据名称静默选择另一模型或套用量化、MTP 和 trust_remote_code。

已有支持模型可以跳过适配及写注册，仍在最终载体调用注册只读检查。新模型须先取得可审查适配、注册结果和允许范围，再将实现复制进隔离构建context，固定所有文件摘要，构建后重新核对运行源码。镜像版本字符串不能代替内容身份。

当前开发参考使用 Qwen3.5-27B BF16、TP4、4096 context、eager；Gemma4-E2B 的既有适配证据仅用于固定版本 BF16 TP1 的文本和图像回验。它们不是其他模型的默认值，不把这些名称和配方写入脚本判断。完整原始配置与权重只读挂载。

建议至少分别提供基础续写、chat、完整SSE、两幅差异图像，以及需要时的长prefill用例。使用预先确定答案的简单问题验证功能；开放内容读完整生成后逐项复核。记录 prompt token 实际覆盖，不把4096配置写成已测4096边界。不用这些功能问题代替正式精度评分或性能验收。

容器仅传入所选设备；物理卡编号和载体可见相对编号分别记录。先核对当前NPU进程、端口、存储、CPU/内存和容器归属。驱动/CANN挂载应与实际基础镜像匹配；保留基础PYTHONPATH，不以覆盖系统路径解决plugin发现问题。

成功默认保留服务；纯临时验证才显式选择stop。精度任务应复用部署交接；其后停止须由本Skill读取精确owned交接执行，不能按进程名清理。远程通过现有授权连接将完整资源及请求放到目标环境执行，不把凭据或私有连接配置打包。

构建应显式记录所选builder。本次开发目标已有基镜像的本地image ID配方使用legacy；它是受限兼容选择，不是全部环境默认，也不在失败后自动切换。Docker已将legacy builder列为deprecated，其他环境应采用与输入和实际Docker版本相符的方法并重新验证。[Docker构建说明](https://docs.docker.com/reference/cli/docker/image/build/)、[弃用说明](https://docs.docker.com/engine/deprecated/)。
